Confidence

confidence = (n · max(p) − 1) / (n − 1)     // n = number of options/levels

Derived from probabilities, so you can recompute or replace it. Flat distribution → low confidence → the model is telling you it does not know. Three-band pattern: act automatically · proceed with caution · do not act. Thresholds scale with the stakes of the action, not with the question.

Calibration is measured across groups of predictions; it does not guarantee that an individual answer is correct.

The nine jagged edges

#Failure modeDo this instead
1Literal readingState the exact condition; put boundary cases in criteria
2Math, numbers, countingKeep arithmetic in code; one Noul per item, sum yourself
3Date and time comparisonExtract parts as Choices; compare in code
4IndirectionReduce hops; name the relevant state directly
5Large state, irrelevant detailFilter first — Jev suffers from context rot
6Adversarial contentState is not treated as hostile. Be explicit; test.
7Contradictory instructions vs criteriaAlign them; never map true→no
8No structural invariantsDon't carry thresholds across types; don't expect sums
9GenerationUse a generative model. Turn extraction into a Choice.

Four rules of thumb

  1. Use code when you can. If a regex or a parser can compute it exactly, it does not belong in a question.
  2. One snap judgement per question. A judgement that depends on three things is three questions, combined with weights you own.
  3. Ask everything in one call. Questions can't contaminate each other, and the state is paid for once. Ignore the answers you don't need.
  4. Two requests only when the second can't be built without the first — new data to fetch, or different options to offer.
