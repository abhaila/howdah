Lesson 01 · System One · ~12 minutes

Three primitives, and why they are not interchangeable

Jev answers in exactly three shapes. Choosing the wrong one does not produce an error — it produces a plausible number that means something other than what you asked.

The shape of every request

There is one endpoint and one idea. You send a state — the thing being judged — and a map of named questions. You get back one typed answer per question, under the same names.

POST https://api.typesafe.ai/v1/systemone

{ "state":     "Help! My payouts have been failing for 3 days.",
  "model":     "jev-latest",
  "questions": { "is_urgent": { "type": "noul", "instructions": "Does this convey urgency?" } } }

→ { "answers": { "is_urgent": { "type": "noul", "noul": 0.95 } },
    "usage":   { "input_tokens": 296, "output_tokens": 20 } }

Two things follow from this and are worth holding onto. The question keys are yours — The key is not sent to the underlying model and is not used in inference. And every question in one request is evaluated independently and in parallel: one answer never becomes context for another.

Why that matters. Because questions don't see each other, batching is free of contamination — and the state is only paid for once. TypeSafe measured 13 questions in one call at 12.2× cheaper and 10.0× faster than 13 calls, with no change in answers. The habit to build: ask everything you might need, then ignore the answers you don't. It is called speculative fan-out.

The three primitives

Noul — one yes/no probability

Returns a single number from 0 to 1: the probability the statement is true. No confidence field — the value is the probability.

{ "type": "noul",
  "instructions": "The findings describe a defect that would break a user-facing behaviour",
  "criteria": { "true": "…what a yes means…", "false": "…what a no means…" } }

Choice — one option from a set

Returns the winning option, a probability for every option (summing to 1), and a confidence. Up to 255 options.

{ "type": "choice",
  "instructions": "Why did this CLI exit before speaking the protocol?",
  "criteria": { "unauthenticated": "Credentials missing or expired",
                "rate_limited":    "Allowance or quota exhausted",
                "crashed":         "Started, then died for another reason" } }

Score — a position on an ordered rubric

Returns a probability-weighted number that can land between levels, plus a legend, the per-level probabilities, and a confidence. Two to ten levels, and they must be ordered.

{ "type": "score",
  "instructions": "How independently shippable is this slice?",
  "criteria": ["Cannot ship without another slice",
               "Ships but leaves a seam",
               "Ships alone and is useful alone"] }

The trap: the same question, two primitives, two answers

This is the part that costs people a day. It is the reason this is lesson one.

Take the ticket I'm not happy with the fit. What are my options here? and ask Is the customer asking for a refund? — first as a Noul, then as a yes/no Choice. TypeSafe publishes what comes back:

Noul noulChoice yesChoice noChoice confidence
0.220.010.990.97

0.22 versus 0.01. Same sentence, same question, same model. A threshold you tuned on the Noul is meaningless on the Choice.

And the identities you would expect to hold do not. Ask Is the customer asking for a refund? and Is the customer asking for something other than a refund? as two Nouls on I was charged twice for the same order. Can someone look into this?:

refundnot_refundsum
0.720.471.19
The rule. Don't rely on expected structural invariance… Don't carry a threshold tuned on a Noul over to a Choice, and don't hold the model to arithmetic identities between separate questions. A Choice is relative — it settles which option wins. A Noul is absolute — and can be low for every option you ask about.

That distinction is the whole lesson. Say it back to yourself before you pick a primitive: am I choosing between options, or am I testing one statement?

Practise: pick the primitive

Five real decisions from Howdah. First press counts.

1. A harness CLI died without speaking the protocol. It was one of: not logged in, out of allowance, a network failure, a bad config, or a crash. Which? (engine/executors/harness-failure.ts)

Choice. Five mutually exclusive causes, exactly one true. You want the full distribution so a spread one parks instead of guessing. A Score is wrong because the causes have no order — network is not between auth and crash.

2. Given one review finding, should it block the merge? (the blocking field, present on 5 of 35 real findings)

Noul. One statement, tested absolutely, per finding — and crucially you ask it once per finding and sum in code. A Choice over findings would force exactly one to win, when the honest answer may be all of them or none.

3. How independently shippable is this slice, before Howdah fans out one real run, worktree and PR per slice? (engine/executors/launch.ts)

Score. The levels are genuinely ordered — each is more shippable than the last — and you want to threshold on the number. Note the jagged edge: use the score to test a threshold, never to reconstruct an exact magnitude between two levels.

4. Does this failed attempt's output mean the harness ran out of allowance? Getting it wrong burns a harness for the whole run. (engine/run.ts:840)

Noul. One statement about one attempt. The tempting answer is Choice over rate limited / not rate limited — but a binary Choice buys you nothing a Noul doesn't already give, and lands you with a `confidence` that means something different from the probability you actually wanted.

5. How much irrelevant detail does this state carry for the question being asked? You want to rank thirty candidate states worst-first.

Score. Ranking needs an ordered magnitude, which is what a Score is for. A Noul gives a probability you could sort on, but it answers is this true, not how much — and the levels are where you get to say what each rung means.

One thing to carry away

Before you write any question, answer this: am I choosing between options (Choice), testing one statement (Noul), or placing something on an ordered rubric (Score)? The three are not three syntaxes for the same thing. They ask different questions and return numbers that are not comparable.
